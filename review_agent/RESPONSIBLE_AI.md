# Responsible AI — Review Analysis Agent (Ashani)

## Explainability
- Summaries use **extractive summarization** — every sentence in a `summary`
  is copied directly from a real review, never generated by an LLM. Anyone
  can trace a summary back to the exact review text behind it.
- `aspects` breaks feedback into categories (taste, texture, difficulty)
  instead of one opaque score, showing *why* a recipe scored the way it did.

## Transparency
- Sentiment scoring uses **VADER**, a rule-based lexicon — not a trained
  black-box model. The same review text always produces the same score, and
  the exact words/punctuation that raise or lower the score are documented
  and publicly known, not hidden inside learned weights.
- Both the raw `sentiment_score` (a number, -1.0 to 1.0) and the
  human-readable `sentiment_label` are returned together, so downstream
  consumers see the precise value alongside an easy-to-read summary.

## Fairness
- Aspect keywords (taste/texture/difficulty) are neutral and not tuned
  toward any particular cuisine, diet type, or price point.
- The agent only reports what reviewers actually said — it doesn't rank,
  filter, or promote any recipe itself; that decision is left to the
  recommendation agent downstream.

## Privacy
- No reviewer usernames, emails, or other personal identifiers are stored,
  logged, or returned by this service — only the review text and derived
  scores.
- The dataset (Food.com recipes/reviews via Kaggle) is public and contains
  no private data beyond what reviewers already posted publicly.

## Misuse Prevention
- Sentiment/aspect output describes **user opinions about a recipe** only —
  never a claim about nutritional or medical safety. That disclaimer is
  handled separately by the orchestrator's `FinalResponse.disclaimer` field.
- Because summaries are extractive (built only from real text), there's no
  risk of hallucinating a claim a reviewer never made.
